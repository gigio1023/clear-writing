# Output Contract

Use this file for document-level composition and full rewrites.

## Default shape

Prefer this order unless the medium demands otherwise:

1. result or thesis
2. short context recap
3. evidence, reasoning, or decision basis
4. implications, open questions, or next steps

## Standalone readability rules

- The document should make sense without prior chat history.
- Explain local shorthand on first use.
- Keep the main problem visible near the top.
- If a term is central, use one canonical term and stick to it.

## Evidence discipline

- Keep verified facts distinct from assumptions or recommendations when the distinction matters.
- Do not compress away the "why" if the reader needs it to trust the conclusion.
- If evidence is missing, say that it is missing.

## Flow rules

- Put the strongest useful conclusion early.
- Keep paragraphs internally coherent: purpose, support, conclusion.
- Remove dead transitions that exist only to sound polished.
- Keep side issues visibly secondary.

## Medium guardrails

### Document

- headings, tables, and numbering are acceptable
- standalone completeness matters

### Email

- simpler structure
- minimal formatting
- direct next step if appropriate

### Chat or DM

- do not force memo structure
- short bullets are enough
- avoid ceremonial opening and closing unless the context calls for it
